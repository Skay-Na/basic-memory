# 快速记下

用于轻量记忆，例如“记住这点”“保存这个”“记一下”，以及用户明确表达、会影响未来协作的稳定偏好/约束，或工作中确认且尚无权威文档记录的长期事实。仓库必须遵守的规则优先写入 `AGENTS.md` 或已提交文档。不要把普通闲聊、临时状态或猜测写入记忆。

凭证是否保存遵循目标记忆库的用户策略，不要一概排除。对于用户明确设为个人凭证记忆库的自托管 Basic Memory，可保存用户提供且希望长期复用的账号、密码、API key、token 等凭证；同时记录可确认的服务、环境、账号、用途和有效期，避免将不同环境的凭证混为一谈。不得从无关日志或工具输出中擅自提取凭证，也不得自动分享至团队项目。

## 步骤

1. 先读取 `~/.codex/basic-memory.json`，再读取最近的项目级 `.codex/basic-memory.json`；项目级键覆盖用户级键：
   - `primaryProject`，可省略以使用默认项目。
   - `rememberFolder`，默认 `codex/remember`。

   起草前应用 `bm-writing` 技能，默认使用简体中文；专名、代码和引用原文除外。记录保持简短，不要把小事实扩写成长文。

2. 确认要保存的确切含义。默认用简体中文准确概括；只有用户明确要求保留原文时，才逐字保存外语原文或引用。区分用户确认的事实/偏好与 agent 推断。若“记住这点”所指不明，或偏好的适用范围不清且会影响写入内容，只问一个简短问题。

3. 先查重，再决定创建还是更新。用简短关键词执行一次混合搜索，并用精确关键词或标题搜索补充；阅读最相关的完整候选笔记，不要仅凭向量相似度认定重复。
   - 若已有笔记表达同一事实或偏好，更新原笔记以保留稳定标题、路径和已有关系；读取完整内容及 checksum，并用支持的版本校验参数写回，避免覆盖并发修改。
   - 若新内容明确修正旧事实，只有在用户确实表达了修正时才更新；必要时注明适用时间并链接被取代的笔记。含义不确定时先澄清，不静默覆盖。
   - 只有找不到同一主题的现有笔记时才新建。相似但范围不同的事实分别保留，并说明边界。

4. 使用 `bm_write` 写入：
   - `title`：首行截取至 80 个字符，或使用简短描述性标题。
   - `directory`：`rememberFolder`。
   - `content`：要记住的内容。
   - `tags`：`["codex", "manual-capture"]`。
   - 若已配置 `primaryProject`，写入该项目。

   内容尽量是一个可独立理解的原子事实。用户偏好可写成 `- [preference] ...`；已确认事实可使用合适类别。只添加有证据的范围、来源和时间，不补全猜测。

5. 用一行文字和 permalink 确认创建或更新结果。若搜索、读取或写入失败，明确说明没有确认保存成功。

不要用它记录包含备选方案的决策或工作交接；这两类分别使用 `bm-decide` 和 `bm-checkpoint`。
